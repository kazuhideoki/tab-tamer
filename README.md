# tab-tamer

Brave 向けに、タブの自動グループ分けと重複防止を統合する個人用ブラウザ拡張。
リポジトリは public とし、当面は一般向けの公開やストア配布を対象にしない。

## 背景

現在は Duplicate Tabs Closer 4.3.5 と Auto-Group Tabs 0.0.24 を併用している。
すでに開いている URL を再度開いた際、重複タブを閉じて既存タブへフォーカスできないことがある。
両拡張の競合は原因の候補であり、まだ確定していない。

## 目指す動作

- URL などのルールに応じて、タブを指定のグループへ自動で整理する。
- すでに開いているページを再度開いた場合、既存タブを再利用して重複を防ぐ。
- 前面で開こうとしたページは、既存タブのあるウィンドウ・グループを含めて適切に表示する。
- バックグラウンドで開く操作や、処理中のユーザーのタブ切替を妨げない。
- グループ分けと重複処理が重なっても、意図しないタブのクローズやフォーカス移動を起こさない。

## 設定の方針

設定は、ブラウザの設定画面ではなく、リポジトリ直下の untracked な `config.toml` で管理する。
このファイルは `.gitignore` で Git 管理から除外する。
グループの判定ルール・名前・色と、重複判定・フォーカスの方針などを設定対象とする。

設定は明示的な反映操作で拡張へ取り込み、一度反映すれば通常利用できるようにする。
動作中に `config.toml` を常時参照する仕組みや、常駐する設定配信用プロセスは設けない。
反映済みの設定はブラウザの再起動後も保持する。

## 導入と設定反映

macOS、Brave、Python 3.11 以上、Node.js 22 以上、OpenSSL が必要。

```sh
# 初回だけ。既存の config.toml があればコピー不要
cp -n config.example.toml config.toml
./tab-tamer validate
./tab-tamer build
```

Brave の `brave://extensions` でデベロッパーモードを有効にし、「パッケージ化されていない拡張機能を読み込む」から、このリポジトリの `dist` を選ぶ。通常利用へ切り替える際は Duplicate Tabs Closer と Auto-Group Tabs を無効にする。

```sh
# config.toml を編集した後はこのコマンドだけで反映
./tab-tamer apply
# 保存済み設定のハッシュと反映日時を確認
./tab-tamer status
```

反映時には短命なタブが開き、保存と署名付き完了応答の確認後に閉じる。CLI の `apply: verified` が成功の目印。通常利用時のサーバー常駐はない。反映済み設定はブラウザ内に保存され、再起動後も使われる。タイムアウト時は保存済みの可能性があるため、`status` で確認する。エラー表示のタブは診断用に残る。

通常の設定変更にはビルドや拡張の再読み込みは不要。拡張のコードを変更した場合は `build` 後に拡張を再読み込みする。`.tab-tamer/identity.json` は固定 ID と認証情報なので保存しておく。`dist` と `.tab-tamer` は Git 管理対象外であり共有しない。

別プロファイルには `--profile 'Profile 1'`、検証用の独立したデータディレクトリには `--user-data-dir /absolute/path` を指定する。`apply` と `status` の両方で同じ指定を使う。

## 設定の意味

全項目と既定値は [config.example.toml](config.example.toml) を参照。`[[groups]]` は先頭から評価し、最初に一致したグループへ整理する。`urls` は完全 URL に対するパターンで、`*` のみ任意の文字列に一致する。正規表現ではなく、大文字小文字を区別する。

- `id` はルールの固定識別子。名前・色を変更しても維持する。
- `strict = false` は、一致しなくなったタブをグループに残す。`true` は自動管理グループから外す。
- `grouping.preserve_manual = true` は手動で付けた名前・色のグループを保護する。設定と同じ名前・色の既存グループは自動管理対象になる。
- `dedup.scope = "all_windows"` は同じプロファイル内の全通常ウィンドウを対象にする。
- `prefer_https = true` は HTTP/HTTPS を同一視する。クエリ・フラグメント・www・大文字小文字は既定では区別する。
- `exclude` は重複防止から除外する URL パターン。グループ分けには影響しない。

新規タブの最初のページ読み込みだけを重複防止の対象とする。既存タブでリンクをたどった場合は閉じない。前面で開いた重複タブは既存タブを表示してから閉じ、バックグラウンドの重複タブは選択を変えずに閉じる。処理途中の切替、URL の変更、対象消失などがあれば保持する側へ倒す。

固定・音声再生中・シークレット・特殊ウィンドウの新規タブ、再読み込み、フォーム送信、履歴復元は対象外。起動直後 5 秒と、作成後 `new_tab_timeout_ms` を超えた読み込みも閉じない。復元操作を完全に識別できるわけではないため、復元時の安全性は引き続き実機で確認する。既存タブの一括重複整理は行わない。

旧設定からの移行には `python3 scripts/migrate-settings.py` を使える。既存 `config.toml` は上書きしない。対応できない保存形式や設定は推測せず停止する。今回の個人設定は 8 グループをローカルに移行済み。

## 検証

```sh
npm test
./tab-tamer validate
./tab-tamer build
npm run test:browser
```

`npm run test:browser` は Brave をヘッドレスで起動し、OS のフォーカスを操作せず実行する。`.test-artifacts` 内の専用プロファイルを使い、結果と診断ログ、実行モードと除外ケース（`run.json`）を同ディレクトリへ保存する。通常利用の Brave で別の作業を続けられる。

OS のフォーカスと外部起動を確認するときだけ `npm run test:browser:headed` を明示的に実行する。この試験は Brave を前面に出すため、通常利用と時間を分ける。ヘッドレス試験の成功は、OS のフォーカスや macOS `open` 経由のリンク配送の合格を意味しない。

実装と検証の境界: [implementation.md](docs/implementation.md)。

調査記録: [既存拡張とフォーカス問題](docs/research.md)、[コマンド反映方式](docs/command-config-research.md)。2026年10月16日に通常プロファイルへ導入し、旧2拡張を無効化した。[通常プロファイルの検証結果](docs/normal-profile-acceptance-2026-10-16.json)。
