# tab-tamer

Brave Browser 向けの、タブの自動グループ分け・重複防止・自動休止を行うブラウザ拡張です。
URL のルールに応じてタブを整理し、同じページを新規タブで開いたときは既存タブを再利用します。

設定はローカルの `config.toml` で管理し、CLI から反映します。反映した設定はブラウザに保存され、再起動後も使われます。通常利用中に常駐サーバーは必要ありません。

## 主な機能

- 現在のタブの URL をコピー（Control＋Shift＋C）、Markdown リンクとしてコピー（Control＋Shift＋M／ポップアップ）。
- 非選択から既定10分での自動休止と、タブごとの常駐指定。
- URL パターンに応じたタブの自動グループ分け。
- 新規タブの初期表示中のリダイレクトや SPA の URL 変更を追跡した重複判定。
- 前面で開いた重複タブから、既存タブのあるウィンドウへの切り替えとグループの展開。
- バックグラウンドで開いた重複タブを、選択を変えずに閉じる処理。
- 手動で編集したグループや、処理中のユーザーのタブ切り替えを保護。

## 必要環境

- macOS
- Brave Browser
- Python 3.11 以上（`python3`）
- Node.js 22 以上（`node`、`npm`）
- OpenSSL、Make

## インストール

リポジトリのルートで、端末から実行します。

```sh
make install
```

`config.toml` がなければサンプルから作成し、設定の検証と拡張のビルドを行います。表示される手順に従って、Brave に拡張を読み込んでください。

1. `brave://extensions` を開き、デベロッパーモードを有効にする。
2. 「パッケージ化されていない拡張機能を読み込む」から、このリポジトリの `dist` を選ぶ。
3. 併用するタブ整理拡張を無効にする。
4. 端末に戻って Enter を押し、設定を反映する。

`apply: verified` と表示されれば、設定の保存と応答の確認は完了です。途中で中止する場合は Ctrl+C を押します。

## 使い方

`config.toml` を編集し、設定を反映します。

```sh
make apply
```

設定だけの変更には、ビルドや拡張の再読み込みは不要です。保存済みの設定ハッシュと反映日時は、次のコマンドで確認できます。

```sh
make status
```

拡張コードを更新した場合は、次を実行します。

```sh
make update
```

ビルド後、Brave の拡張管理画面で Tab Tamer を手動で再読み込みし、端末で Enter を押してください。保存済みの設定を確認します。設定ファイルも変更した場合は、続けて `make apply` を実行します。

### URL・Markdownリンクをコピー

現在のタブで **Control＋Shift＋C** を押すと、URL だけをコピーします。

**Control＋Shift＋M** を押すか、Tab Tamer のポップアップで「現在のタブをMarkdownでコピー」を押すと、`[タイトル](URL)` 形式でコピーします。macOS でも Command ではなく Control です。設定の反映やタブ整理機能の有効化は不要です。

タイトルと URL はエスケープせず、そのままコピーします。タイトルに含まれる改行・タブは空白に置き換えます。

通常ページでは右上に「URLをコピーしました」または「Markdown形式でコピーしました」を約2秒表示します。失敗通知は5秒表示します。拡張更新前から開いている通常の Web ページにも、コピー操作時に通知処理を追加するため、ページの再読み込みは不要です。

Braveの設定画面など、ページ内に通知を表示できない場合は、OS の通常の通知でコピーした形式または失敗理由を表示します。コピー時に詳細ポップアップは自動で開きません。OS 側で Brave の通知を許可してください。画面共有中の通知抑制や集中モードなど、OS の設定によっては通知が表示されません。

結果は拡張アイコンの `OK`／`ERR` バッジとポップアップに表示します。バッジは直近の実行結果として次の実行まで残ります。ツールバーに Tab Tamer を固定するとショートカットの結果も確認できます。

ポップアップには実際のショートカット割り当ても表示します。未割り当ての場合や更新後に以前の割り当てが残っている場合は、`brave://extensions/shortcuts` で URL コピーを Control＋Shift＋C、Markdown コピーを Control＋Shift＋M に設定してください。旧コピー拡張と競合する場合は、旧拡張側の割り当てを解除してください。

コピーには `clipboardWrite`、`offscreen`、`notifications` 権限と、コピー操作時の通知処理追加に `activeTab`・`scripting` 権限を使用します。通知処理の追加はコピー元ページの最上位フレームだけを対象とし、クリップボードの読み取りは行いません。複数タブ・グループの一括コピーは対象外です。

### 自動休止と常駐

タブを非選択にしてから既定で10分後に、ブラウザ標準の `tabs.discard` で休止します。バックグラウンドで作成したタブは作成時点から数えます。実行は1分ごとの確認なので、期限から通常最大約1分遅れ、端末のスリープやブラウザの都合でさらに遅れる場合があります。

各ウィンドウの選択中タブは、背面ウィンドウでも休止しません。タブを選ぶとブラウザが元のURLを再読み込みします。ウィンドウを前面にするだけで非選択の休止タブを復帰させる処理はありません。URLやグループは維持し、独自の休止画面への置換や自動で閉じる機能は追加していません。既存の新規重複タブを閉じる機能は従来どおりです。

ポップアップで現在のタブの常駐状態と休止・保護の理由を確認し、「常駐をオン／オフにする」で変更できます。ページまたは拡張アイコンの右クリックにも切り替えと「Pinに連動」の操作があります。常駐操作のエラーはポップアップで確認してください。コピーの `OK`／`ERR` バッジは自動休止や常駐操作では変更しません。

| 指定 | 動作 |
| --- | --- |
| Pinに連動（初期値） | 通常タブは常駐オフ、Pinしたタブは常駐オン |
| 手動で常駐オン | Pin状態に関係なく自動休止から除外 |
| 手動で常駐オフ | Pin状態に関係なく休止対象 |
| Pinに連動へ戻す | 手動指定を解除 |

拡張更新前から開いていた通常のWebページでも、ページを再読み込みせずに常駐を切り替えられます。操作時の `activeTab`・`scripting` 権限で、最上位フレームの識別子だけを読み書きします。入力内容や本文には触れず、既存の入力・通話の保護状態が確認できないページは引き続き自動休止を保留します。

常駐オンからオフになると、その時点から設定時間分の猶予を取り直します。手動でオフを選び直した場合も同様です。

```toml
[suspension]
enabled = true
idle_minutes = 10
```

`idle_minutes` は1〜10080の整数です。既存の設定ファイルにこの節がなくても、既定値を補います。設定は従来どおり `make apply` で反映します。自動休止は設定が未反映でも既定値で動作します。

期限と実行中のタブの対応は `chrome.storage.session`、手動指定は `chrome.storage.local` に保存します。worker停止時に消える `setTimeout` には依存せず、`chrome.alarms` が失われていればworker起動時に作り直します（既存のアラームは延期しません）。ブラウザ再起動・拡張再読み込みでセッション状態がなくなった場合は、復元タブごとに設定時間分の猶予を設けます。

手動指定の復元には、タブのページの `sessionStorage` に保存するランダムな識別子を使います。URLや再利用されるタブIDだけでは照合せず、同じURLの別タブにまとめて適用しません。通常の新規作成・複製タブには別の識別子を割り当てます。識別子の衝突を検出した場合は該当タブを維持し、ポップアップから再指定を求めます。休止中の復元タブを識別のためだけに起こすことはなく、ページが読み込まれた時点で指定を復元します。

**永続化の限界：** ブラウザによるページのセッション復元が必要です。サイトが `sessionStorage` を削除した場合、保存が禁止された場合、復元情報が失われた場合には指定を復元できません。特殊ページや保存できないページでは手動の常駐指定を受け付けず、エラーを表示します。ページ自身からも識別子にアクセスできるため、悪意あるページに対する改ざん防止用の識別子ではありません。ブラウザ終了時のセッションが復元されない通常の新規タブへ、過去の指定を引き継ぐこともありません。

### 自動休止の保護範囲

- `tabs.Tab.audible` が真のタブは維持します。ミュートや無音の再生を音声再生中と判定できる保証はありません。
- HTTP(S)ページの各フレームで、実際の `beforeinput`・`input`・`change` と、入力欄やcontenteditable内のキー操作を検知したら、文書が切り替わるまで維持します。送信・保存の成否は判断しないため、送信済みでも維持される場合があります。入力値、キーの内容、ページ本文は読み取り・保存・送信しません。
- 文書の開始時から `getUserMedia`・`getDisplayMedia` で新しく取得された有効なトラックと、生成後に閉じられていない `RTCPeerConnection` の有無を監視します。検知した通話・カメラ・マイク・画面共有・WebRTC接続は維持します。音声・映像データを取得・録画・送信することはありません。
- 休止直前に全フレームへ状態を問い合わせます。応答できないフレーム、拡張更新前から開いているページ、保護スクリプトが実行できないページは維持します。選択・遷移・常駐変更などが確認中に発生した場合も処理を中止します。
- `autoDiscardable = false`、分割表示中、読み込み中、シークレット、特殊URL、通常以外のウィンドウも対象外です。1つのタブで失敗しても他のタブの処理を続け、失敗は1分以上空けて再試行します。

**検出の限界：** サイト独自の編集領域、イベントを発生させない自動入力、復元・読み込み済みの未保存データ、閉じたShadow DOM内部の一部操作を完全には検出できません。メディア監視はページと同じ実行環境でAPIをラップするため、サイトによる置き換え・妨害、別の経路や別の実行環境で取得済みの接続を網羅できず、サイトとの互換性にも限界があります。通話・共有を完全に保護すると保証する表示はしません。保持したい編集・会議タブは常駐オンを使ってください。Brave自身のメモリセーバーや他の拡張による休止は、この常駐指定の制御対象外です。

追加権限は、永続タイマー用の `alarms` と操作用の `contextMenus` だけです。全ページへの新しいホスト権限、`debugger`、`tabCapture` は追加しません。Chromeの公開APIには全サイトの通話・共有を一括照会する機能がなく、`tabCapture.getCapturedTabs` もこの拡張自身の取得状況に限られるため採用していません。参照：[Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs)、[Sessions API](https://developer.chrome.com/docs/extensions/reference/api/sessions)、[Tab Capture API](https://developer.chrome.com/docs/extensions/reference/api/tabCapture)、[取得元拡張ごとの照会処理](https://chromium.googlesource.com/chromium/src/+/main/chrome/browser/extensions/api/tab_capture/tab_capture_api.cc)。

### CLI

Make を使わずに、各操作を直接実行することもできます。

| コマンド | 用途 |
| --- | --- |
| `./tab-tamer validate` | 設定ファイルを検証する |
| `./tab-tamer build` | 拡張を `dist` にビルドする |
| `./tab-tamer apply` | 設定をブラウザへ反映する |
| `./tab-tamer status` | ブラウザに保存済みの設定ハッシュと反映日時を確認する |

別の Brave プロファイルを使う場合は、`apply` と `status` の両方に同じ指定を付けます。

```sh
./tab-tamer apply --profile 'Profile 1'
./tab-tamer status --profile 'Profile 1'
```

独立したデータディレクトリには `--user-data-dir /absolute/path`、別の設定ファイルには `--config /path/to/config.toml` を指定できます。全オプションは `./tab-tamer --help` で確認できます。

## 設定

設定項目と既定値は [config.example.toml](config.example.toml) を参照してください。

### グループ分け

`[[groups]]` は先頭から評価し、最初に一致したグループへタブを整理します。

```toml
[[groups]]
id = "example"
name = "Example"
color = "blue"
urls = ["https://example.com/*"]
strict = false
```

- `id` はルールの固定識別子です。名前や色を変えても維持してください。
- `urls` は完全 URL に対するパターンです。`*` が任意の文字列に一致し、大文字小文字は区別します。正規表現は使えません。
- `strict = false` では、ルールに一致しなくなったタブもグループに残します。`true` では、自動管理グループから外します。
- `grouping.preserve_manual = true` では、手動で名前や色を付けたグループを保護します。設定と同じ名前・色の既存グループは、自動管理の対象になります。

### 重複防止とフォーカス

- `dedup.scope = "all_windows"` では、同じプロファイル内の全通常ウィンドウを対象にします。
- `dedup.prefer_https = true` では、HTTP と HTTPS を同一視します。
- URL 末尾のスラッシュは既定で無視します。クエリ、フラグメント、`www`、大文字小文字は既定で区別します。
- `dedup.exclude` に指定した URL パターンは、重複防止から除外します。グループ分けには影響しません。
- `focus.foreground` は前面で開いた重複タブから既存タブへの切り替え、`focus.expand_group` はそのグループの展開を制御します。

## 動作上の制約

重複防止は、新規タブの初期表示を対象にします。読み込み完了後、URL が `dedup.settle_ms` の間変わらなくなった時点で判定します。メイン文書の完了通知後もタブが読み込み中なら、元の `dedup.new_tab_timeout_ms` の範囲内で完了を待って再判定します。既存タブでリンクをたどった場合は閉じません。既存タブの一括重複整理も行いません。

初期表示中でも、ページ上でクリックやキー入力などのユーザー操作があれば、そのタブの重複判定を終了します。操作の検知には HTTP(S) ページのコンテンツスクリプトを使い、操作の有無だけを通知します。入力内容やページ本文は取得・送信しません。

固定・音声再生中・分割表示中の新規タブ、タブの複製、再読み込み、フォーム送信、履歴復元は閉じないように扱います。シークレットや特殊ウィンドウは対象外です。起動直後の 5 秒間と、作成後 `dedup.new_tab_timeout_ms` を超えた読み込みも閉じません。

処理中のタブ切り替えや URL 変更、対象の消失などを検知した場合は、タブを保持します。このため、重複が残ることがあります。復元操作を完全に識別することはできず、実サイトの認証や復元時の動作は利用環境でも確認が必要です。

## トラブルシューティング

設定の反映・確認時には一時的なタブが開き、応答の確認後に閉じます。タイムアウトした場合でも設定は保存されている可能性があるため、`make status` で確認してください。エラーが表示されたタブは診断用に残ります。

`config.toml`、`dist`、`.tab-tamer` は Git 管理対象外です。`.tab-tamer/identity.json` には拡張の固定 ID と認証情報が含まれるため、保持してください。`dist` と `.tab-tamer` は共有しないでください。

## 開発・テスト

```sh
npm test
./tab-tamer validate
./tab-tamer build
npm run test:browser
```

`validate` には `config.toml` が必要です。未作成の場合は `config.example.toml` をコピーしてください。

`npm run test:browser` は、専用プロファイルのヘッドレス Brave で実行します。通常利用中の Brave のフォーカスは操作しません。結果、診断ログ、実行モードと除外ケースは `.work/brave-*` に保存します。

OS のフォーカス移動や macOS `open` 経由のリンク配送を確認する場合は、可視モードの試験を実行します。Brave が前面に出るため、通常の作業と時間を分けてください。

```sh
npm run test:browser:headed
```

ヘッドレス試験の成功だけでは、OS のフォーカス移動や外部アプリからのリンク配送を検証したことにはなりません。
